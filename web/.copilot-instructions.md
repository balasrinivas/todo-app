# Frontend-Specific GitHub Copilot Instructions for ToDo App Web

## TypeScript Standards

- **Strict Mode**: Enable strict TypeScript mode with no `any` types, no implicit `any`
- **Explicit Types**: Every variable, parameter, and return type must be explicitly typed
- **Interface Naming**: Use PascalCase for interfaces (e.g., `TodoItem`, `Category`)
- **Type Imports**: Use `import type` for type-only imports
- **Generic Types**: Leverage TypeScript generics for reusable components and hooks
- **Union Types**: Use union types for state management and API responses
- **Never Types**: Use `never` for exhaustive type checking in switch statements
- **Utility Types**: Utilize built-in utility types (Partial, Pick, Omit, etc.)

## React Patterns

- **Functional Components**: Use functional components with hooks, no class components
- **Hooks**: Prefer custom hooks for reusable logic
- **Props**: Define props interfaces for all components
- **Event Handlers**: Type event handlers explicitly (e.g., `onClick: (event: React.MouseEvent<HTMLButtonElement>) => void`)
- **State**: Use `useState` with proper typing, avoid `useReducer` unless complex state
- **Effects**: Minimize `useEffect` usage, prefer declarative patterns with TanStack Query
- **Refs**: Type refs with `useRef<T>` or `React.RefObject<T>`
- **Context**: Use Context API sparingly, prefer prop drilling for simple cases

## TanStack Query Patterns

- **Query Client**: Configure QueryClient in main.tsx with default options
- **Query Hooks**: Use `useQuery` for data fetching, `useMutation` for mutations
- **Query Keys**: Define query keys as constants in separate files
- **Error Handling**: Handle error states in components with proper UI feedback
- **Loading States**: Show loading indicators during query execution
- **Cache Management**: Use `invalidateQueries` and `setQueryData` appropriately
- **Optimistic Updates**: Implement optimistic updates for better UX
- **Retry Logic**: Configure retry behavior in QueryClient defaults

## Axios Patterns

- **Centralized Client**: Create Axios instance in `/api/client.ts` with baseURL from env
- **Interceptors**: Add request/response interceptors for logging and error handling
- **Typed Responses**: All API functions return typed Promises
- **Error Types**: Define custom error types for API failures
- **Timeout**: Configure reasonable timeouts for all requests
- **Headers**: Set default headers (Content-Type, Authorization if needed)
- **Cancellation**: Use AbortController for request cancellation

## Component Structure

- **File Naming**: PascalCase for components (e.g., `TodoList.tsx`)
- **Export Style**: Named exports only, no default exports
- **Props Interface**: Define props interface within component file or separate types file
- **JSX Structure**: Use semantic HTML elements with proper accessibility
- **Styling**: Use CSS modules or styled-components (TBD based on project choice)
- **Composition**: Prefer composition over inheritance
- **Children Types**: Type `children` prop as `React.ReactNode`
- **Event Props**: Define event handler props with proper Event types

## Testing Patterns (Vitest + RTL)

- **Framework**: Use Vitest as test runner with React Testing Library
- **Test Files**: Co-locate test files with components (e.g., `Component.test.tsx`)
- **Queries**: Prefer user-centric queries (getByRole, getByText) over implementation details
- **Mocking**: Mock API calls and external dependencies
- **Async Testing**: Use `waitFor` and `screen.findBy*` for async operations
- **Custom Render**: Create custom render function with providers (QueryClient, etc.)
- **Test Naming**: `describe('ComponentName', () => { it('should...', () => {}) })`
- **Coverage**: Aim for high coverage with meaningful tests
