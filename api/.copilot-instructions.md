# Backend-Specific GitHub Copilot Instructions for ToDo App API

## Python Standards

- **Python Version**: Use Python 3.11+ for all development
- **Dependency Management**: Use pip with virtual environment (venv)
- **Requirements**: Pin all versions in requirements.txt (e.g., fastapi==0.111.0)
- **Logging**: Use Python logging module with one logger per module: `logger = logging.getLogger(__name__)`
- **Imports**: Organize alphabetically, separate standard library, third-party, and local imports
- **Type Hints**: Use strict typing with `from __future__ import annotations` where appropriate
- **Constants**: Define magic numbers and strings as named constants
- **Docstrings**: Every function, class, and module must have Google-style docstrings

## FastAPI Patterns

- **Application Structure**: Use FastAPI app instance in main.py with lifespan events
- **Routers**: Organize endpoints in separate router files under routes/
- **Dependency Injection**: Use Annotated[AsyncSession, Depends(get_db)] for database sessions
- **Middleware**: Configure CORS, logging, and other middleware in main.py
- **Startup/Shutdown**: Use lifespan context manager for database initialization and cleanup
- **Response Models**: Always use Pydantic response models, never return raw data
- **API Versioning**: Include version in URL path (e.g., /api/v1/todos)

## SQLAlchemy Async Patterns

- **Engine**: Use async engine with aioodbc driver for SQL Server
- **Session**: Always use AsyncSession, never sync Session
- **Models**: All models inherit from Base with id (UUID), created_at, updated_at
- **Relationships**: Use async-compatible relationship loading (selectinload, joinedload)
- **Queries**: Use async select() with execute() for all database operations
- **Transactions**: Use async context managers for transaction management
- **Connection String**: Use environment variable for database URL with Windows Authentication

## Alembic Workflow

- **Initialization**: Use `alembic init alembic` for initial setup
- **Revisions**: Create migrations with `alembic revision --autogenerate -m "message"`
- **Upgrades**: Apply migrations with `alembic upgrade head`
- **Downgrades**: Support downgrade paths in all migrations
- **Environment**: Configure alembic.ini with async database URL
- **Models**: Import all models in env.py for autogeneration
- **Never Direct Schema Changes**: All database changes through migrations only

## Pydantic v2 Patterns

- **Models**: Use BaseModel for all schemas
- **Validators**: Use @model_validator and @field_validator (v2 syntax)
- **Serialization**: Use model_dump() instead of dict()
- **Validation**: Leverage Pydantic's built-in validation for all inputs
- **Aliases**: Use Field(alias="...") for API field mapping
- **Response Models**: Separate request and response schemas
- **Nested Models**: Use nested Pydantic models for complex data structures

## Error Handling

- **Custom Exceptions**: Define specific exception classes in exceptions/
- **HTTP Exceptions**: Use FastAPI's HTTPException with appropriate status codes
- **Global Handlers**: Implement exception handlers in main.py for consistent error responses
- **Logging**: Log all exceptions with appropriate levels (ERROR, WARNING)
- **Validation Errors**: Handle Pydantic validation errors with custom messages
- **Database Errors**: Catch SQLAlchemy exceptions and convert to HTTP errors
- **Never Swallow Exceptions**: Always log and re-raise or handle explicitly

## Testing Patterns (pytest + pytest-asyncio)

- **Framework**: Use pytest with pytest-asyncio for async tests
- **Fixtures**: Define async fixtures for database sessions and test data
- **Test Database**: Use separate test database with fixtures
- **Coverage**: Aim for >90% code coverage with pytest-cov
- **Naming**: `test_function_name_describes_what_it_tests`
- **Structure**: Arrange-Act-Assert pattern in all tests
- **Mocking**: Use pytest-mock for external dependencies
- **Async Tests**: Mark async test functions with @pytest.mark.asyncio
